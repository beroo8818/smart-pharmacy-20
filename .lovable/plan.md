# خطة التنفيذ — نظام إدارة أرصدة ومنصرفات المستشفى

طلبك ضخم جدًا (27 محورًا، عشرات الصفحات والجداول، منطق حسابي حساس). تنفيذه دفعة واحدة سيكسر الواجهة ويُدخل أخطاء صامتة في حساب الأرصدة. هنقسمه على **6 مراحل قابلة للاختبار**، كل مرحلة تُسلَّم وتُختبر قبل اللي بعدها.

---

## المرحلة 1 — الأساس (مركز التشغيل + الرصيد المتوقع الصحيح)
**الأهم والأكثر إلحاحًا — يحل مشكلة double counting الحالية.**

1. صفحة **مركز التشغيل** (Home) بـ 6 كروت: رفع شهري، تحديث أسبوعي، حركة، Google Sheet/CSV، تحميل قالب، مقارنة شهر بشهر. كل كارت = عنوان + وصف + 3 خطوات + زر.
2. إصلاح **منطق الرصيد المتوقع اليوم** في `src/lib/analytics.ts` و`continuousAnalysis.ts`:
   - لكل (item + location): استخراج `latestSnapshotDate`
   - تطبيق الحركات فقط إذا `transaction_date > latestSnapshotDate` (منع double counting بعد التحديث الأسبوعي)
   - عرض: رصيد آخر ملف / تاريخه / أيام منذ آخر رصيد / الرصيد المتوقع / درجة الثقة
3. مكوّن `<NextStep>` لإضافته آخر كل صفحة لاحقًا.

## المرحلة 2 — استيراد Excel ذكي + شاشة مراجعة
1. إعادة كتابة منطق قراءة Excel:
   - تجاهل فقط: صف فارغ بالكامل / عنوان واضح / إجمالي / توقيع / فاصل بدون بيانات
   - أولوية الاسم: المنظومة → العلمي → التجاري
   - **استكمال من الصف السابق** (اقتراح فقط، لا حفظ تلقائي)
   - تصنيف: جاهز / يحتاج مراجعة / متجاهل فعليًا
2. شاشة **"مراجعة قبل الحفظ"** بـ 3 تبويبات + جدول كامل + أزرار (اعتماد / تعديل / تجاهل / إصلاح تلقائي / اعتماد الكل / تصدير تقرير المشاكل).
3. كارت **جودة الملف** بنسبة محسوبة وتصنيف (ممتاز/جيد/يحتاج مراجعة/ضعيف).
4. حفظ المتجاهل فعليًا في `import_ignored_rows` مع السبب.
5. زر **تحميل قالب Excel موحد** (14 عمود بالعربي).
6. تطبيق نفس المنطق على **Google Sheet/CSV** مع `snapshot_date` إلزامي.

## المرحلة 3 — تسجيل الحركات + قاعدة البيانات الصلبة
1. صفحة **تسجيل وارد/منصرف** محسّنة:
   - بحث عن الصنف من `inventory_movements` + `active_ingredient_dictionary` (مش كتابة حرة)
   - بحث عن الموقع من `locations`
   - عرض الرصيد قبل وبعد + أيام التغطية + تحذيرات حد الأمان
2. تطبيق `batch_kind` (monthly_snapshot / weekly_snapshot) + `snapshot_date` بشكل صحيح.
3. إضافة `first_active_date` لحساب الصرف اليومي للأصناف الجديدة (قسمة على الأيام الفعلية بدل 30).

## المرحلة 4 — قاموس المواد الفعالة + التحليل الآمن
1. تحسين استخراج: `active_ingredient` + `strength` + `dosage_form` + `unit` مع `confidence_score`.
2. توحيد المسميات (tab→tablet, cap→capsule, إلخ).
3. منع التجميع الخطر: لا دمج عند اختلاف التركيز/الشكل/الوحدة/الـ route.
4. فلتر **"طريقة التحليل"** في كل التحليلات (افتراضي: مادة+تركيز+شكل).
5. صفحة **تفاصيل المجموعة العلاجية** (موجودة جزئيًا، تحتاج تكميل).

## المرحلة 5 — مركز العمل اليومي + التوصيات الآمنة
1. حساب التوصيات فعليًا حسب `therapeutic_group_key` المعتمد.
2. قواعد صرف/تحويل آمنة:
   - `Main Store Required Reserve = ΣBranches ADC × Target Days`
   - لا اقتراح صرف إذا يخالف حد الأمان
   - عرض قبل/بعد لكل توصية
3. استبعاد الأصناف غير المعتمدة من توصيات التنفيذ → "راجع البيانات".
4. تحسين مقارنة شهر بشهر حسب المجموعة العلاجية + 6 أقسام تحليلية.

## المرحلة 6 — التقارير + الصلاحيات + النسخ الاحتياطي
1. 10 تقارير Excel بهيدر موحد (مستشفى/تقرير/شهر/snapshot/مصدر/طريقة/تاريخ/مستخدم/ثقة).
2. تطبيق الصلاحيات على مستوى الاستعلام و RLS:
   - `sub_pharmacist` لا يرى إلا `assigned_location_id`
   - عرض/إخفاء كامل في Dashboard والتنبيهات والتقارير
3. صفحة **النسخ الاحتياطي** لـ `system_admin` + تنبيه إذا > 7 أيام.
4. صناديق "الخطوة التالية" في كل الصفحات.

## ملاحظات حرجة

- **الأهم تقنيًا**: إصلاح double counting في المرحلة 1 — لأنه يفسد كل القرارات الحالية.
- **الجداول الموجودة كافية** لمعظم الخطة. هتحتاج إضافة: `first_active_date` على `item_master` (موجود فعلًا ✓)، حقول `confidence` على المجموعات، جدول `backups_log` صغير.
- **التطبيق على نسخة الديسكتوب**: قاعدتك السابقة كانت "كل التحديثات تتعمل على الديسكتوب زي الويب". هنطبق كل مرحلة على `src/` ثم نزامن مع `desktop/src/` في نفس الـ commit.
- المراحل 4 و5 و6 لا يمكن البدء فيها قبل أن تختبر المراحل 1-3 على بيانات حقيقية لديك.
