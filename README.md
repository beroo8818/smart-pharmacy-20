# دواء | Dawa

برنامج لإدارة أرصدة ومنصرف المخزن والصيدليات الفرعية، واستيراد Excel/CSV، ومتابعة النقص والتغطية والتحويلات. لا يسجل بيانات مرضى.

## تنزيل البرنامج للمستخدم

الإصدار المحلي الجديد **1.1.1 للتجربة المحلية، وليس إصدار إنتاج معتمدًا للمستشفى**. يتضمن ترتيب الشغل فوق والإدارة تحت، وفصل نقص التوزيع عن فجوة شراء المستشفى. قائمة الدعم رأي موثق فقط وغير منفذة.

من [صفحة التنزيل](https://github.com/beroo8818/smart-pharmacy-20/releases) اختر الإصدار المنشور المطلوب؛ وجود كود 1.1.1 لا يثبت انتهاء رفع ملفاته. للإصدار الجديد تكون الأسماء:

- `Dawa-Portable-1.1.1.zip`: فك المجلد كاملًا ثم افتح `Dawa.exe`. لا يحتاج المستخدم Node أو CMD. للنقل بعد الاستخدام أغلق البرنامج وانقل المجلد كاملًا بما فيه `DawaData`.
- `Dawa-Setup-1.1.1-x64.msi`: مثبت Windows مع اختصارات باسم دواء. بياناته منفصلة عن البرنامج في AppData/Roaming/Dawa. فحصت محتوياته دون تنفيذ تثبيت أو إزالة لهذا الإصدار. أكمل مستخدم واحد معالج الإصدار السابق 1.1.0؛ ذلك ليس اختبار قبول كاملًا للمثبت الجديد.
- `Dawa-Guide-ar.pdf`: دليل مصور بالعربية من 19 صفحة.
- `SHA256SUMS.txt`: بصمات ملفات التوزيع للتحقق منها.

ملفات التوزيع لا تحتوي بيانات المستشفى. حساب القاعدة المحلية الجديدة الافتراضي `admin` وكلمته `admin123`؛ يجب تغييرها قبل إدخال بيانات فعلية. البرنامج غير موقع بشهادة ناشر؛ لا تعطل حماية Windows لتشغيله.

زر **Code > Download ZIP** ينزل الكود للمطور، وليس البرنامج الجاهز. ملفات التشغيل موجودة في Releases.

## الويب والديسكتوب

- `src/`: واجهة الويب التي تعتمد على قاعدة PostgreSQL وخدمات Supabase المتوافقة معها.
- `desktop/`: تطبيق Electron بقاعدة SQLite محلية.
- `shared/`: الحسابات ومكونات التقارير والصلاحيات المشتركة.
- `supabase/migrations/`: ترحيلات القاعدة؛ الستة المضافة في أكتوبر 2026 لم تطبق على قاعدة التشغيل الحية من هذه المهمة.

**رفع الكود إلى GitHub لا ينشر موقعًا ولا يفعّل القاعدة.** نسخ الديسكتوب مستقلة ولا تتزامن مع بعضها أو مع الويب. لا تشارك ملف SQLite عبر مجلد شبكي. تشغيل المستشفى مركزيًا يحتاج خادمًا معتمدًا ومسؤول تشغيل واتصالًا وصلاحيات ونسخًا احتياطيًا مختبرة.

## للمطور

ابدأ بقراءة [حالة التسليم](docs/current-delivery.ar.md)، و[توافق الشاشات](docs/screen-parity.ar.md)، و[تسليم قاعدة الويب](docs/web-database-handoff.ar.md). بعض الشاشات القديمة والتوصيات ما زالت مختلفة، ولا ندعي تطابق التطبيقين بالكامل.

لإعداد الويب محليًا، ثبت الاعتماديات من ملفات المشروع، وانسخ `.env.example` إلى `.env.local` وضع عنوان مشروع الاختبار ومفتاحه العام فقط، ثم شغل `npm run dev`. لا تضع مفتاح service-role في المتصفح أو GitHub. يلزم وجود قاعدة اختبار متوافقة، وليس مجرد مفتاح اتصال.

بناء Windows يستخدم `scripts/build-icon.ps1` ثم `scripts/build-windows.mjs --msi`، ويتطلب اعتماديات الديسكتوب وربط SQLite الأصلي بإصدار Electron قبل التغليف. `--dir` يبني مجلدًا محمولًا. لا يفترض البناء أن مكتبة SQLite الخاصة بـ Node صالحة لـ Electron؛ افحص الحزمة بـ `scripts/check-windows-package.cjs` قبل توزيعها. فحص ICE لم يعمل في بيئة التجهيز؛ بُني الملف المرفق بخيار `--skip-ice` الصريح، وليس ذلك بديلًا لاختبار مثبت كامل.

## الحدود والاختبارات

نجحت اختبارات معزولة: 180 للويب، 18 لواجهة الديسكتوب، 154 لـ SQLite، 113 لـ PostgreSQL، 25 للنقل والاسترجاع، و42 لسيناريو مدير ومخزن وفرعين. تشمل اختبارات التوصيات فرق نقص التوزيع وفجوة إجمالي المستشفى. هذه ليست تجربة ميدانية داخل المستشفى؛ نتائج الحزمة المنقولة تسجل في ملف تسليم كل إصدار.

قرارات التوصيات الجديدة تحفظ في قاعدة الديسكتوب وتدخل النسخ والاسترجاع؛ تسجيل قرار كمنفذ لا يحرك المخزون. ملفات Excel الأصلية والقرارات القديمة في المتصفح ليست ضمن نسخة القاعدة إلا وفق الاستيراد الموثق.

لا ترفع قواعد بيانات أو Excel مستشفى أو نسخًا احتياطية أو كلمات مرور أو مفاتيح خدمة. فحص `node scripts/audit-publication.mjs` حاجز آلي مبدئي وليس شهادة أمنية. لم ينفذ نشر قاعدة أو ربط شبكة مستشفى ضمن هذا الإصدار.
