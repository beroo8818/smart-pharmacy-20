# حالة دفعة الحفظ المباشر والتقارير

## المنفذ محليًا

- البند 3: حفظ تقارير الفروع مباشرة بعد التحقق، مع تأكيد التصحيح ومنع التكرار والحفاظ على السجل. التقارير القديمة المعلقة لا تفعل تلقائيًا.
- البند 4: مكونات مشتركة للتنبيهات الرئيسية ومركز التقارير ودليل التشغيل في الويب والديسكتوب. الشاشات المتقدمة القديمة محفوظة؛ لم توحد كل صفحات التطبيق.
- البند 5: تقارير مستقلة للمستشفى أقل من 30 يومًا، والمخزن أقل من 30 أو 14، ورصيد صفر مع طلب، وبيانات غير كافية. احتياج المخزن مبني على منصرف الفروع فقط.
- البند 7: أحد عشر سيناريو تشغيل؛ يظهر منها ما يناسب الصلاحيات الحالية، مع دليل PDF يتضمن لقطات تدريبية ورسومات خطوات موسومة بوضوح.

## المؤجل أو غير المنشور

- اكتمل محليًا البند 2 بعد موافقة المستخدم: 50 بند صلاحية وتعدد الفروع، مع قيود قاعدة وواجهة. تفعيل قاعدة الويب الحية لم يتم؛ راجع current-delivery.ar.md.
- بعد تأكيد المستخدم اكتمل تحديث الشاشات عند الحفظ والعودة للنافذة، ودورة قراءة مشتركة كل دقيقة أثناء الظهور، مع اختيار التغطية المسجلة أو المتوقعة. لا توجد خدمة والبرنامج مغلق؛ راجع automatic-refresh.ar.md للحدود والمتبقي.
- لم تنشر هذه الدفعة على GitHub ولم تطبق ترحيلات على قاعدة الويب الحية، ولم تنقل بيانات المستشفى أو تعدل ملفات Excel الخاصة بها.
- لا يوجد خادم مستشفى أو مزامنة أجهزة جديدة. الديسكتوب المحلي ليس قاعدة مشتركة للشبكة.
- صور الدليل من واجهة تدريبية تستخدم المكونات المشتركة، ولا تثبت تشغيل نسخة Electron الفعلية أو تفعيل قيود قاعدة الويب الحية.

## التفعيل اللاحق

يحدد مالك قاعدة الويب بيئة اختبار مطابقة، ويأخذ نسخة احتياطية ويطبق الترحيلات المتبقية بالترتيب كما في دليل المدير، ثم يختبر بحسابات فعلية قبل النشر. نجاح الاختبارات المعزولة لا يحل محل هذه الخطوة. لا تفتح منافذ أو تشارك ملف SQLite على الشبكة.
