# رأي وتصميم مبدئي لقائمة الدعم - غير منفذة

طلب المستخدم الرأي فقط، ولم يطلب تنفيذ هذه الميزة الآن. لم تضف شاشة أو صلاحيات أو جداول أو حركات مخزون للدعم.

## الهدف

بدل اتصال الدعم بكل صيدلية، ينشر موظف مخول طلب تجهيز وتحويل فعليًا له رقم، وجهة استلام، وموعد رد، وأصناف محددة بالكود والتركيز والشكل والوحدة والكميات المطلوبة. لا يكفي اسم تجاري عام، ولا تخلط قرصًا بشريط أو علبة دون معامل تحويل معتمد.

## سير العمل المقترح

1. الدعم يجهز قائمة مثل 15 صنفًا، ويختار الفروع المستهدفة وجهة الاستلام. النشر لا يخصم رصيدًا.
2. كل فرع يرى الطلب ويرد بالكمية التي يستطيع توفيرها، مع تاريخ رصيده. الصفر رد صحيح بمعنى غير متاح، أما عدم الرد فلا يعتبر صفرًا. لا يرى الفرع أرصدة الفروع الأخرى.
3. الدعم يراجع العروض ويخصص منها المطلوب فقط، بحيث لا تتجاوز التخصيصات إجمالي الطلب، ولا تستنزف رصيد الصيدلية أو تتجاهل الأصناف الحرجة. يلزم قفل التخصيص عند التزامن وتسجيل كل تصحيح.
4. المسؤول المخول يسجل تحويلًا فعليًا واحدًا برقم مستند فريد، أو يربط الطلب بحركة مسجلة بالفعل. الطلب والرد والتجهيز لا تنشئ ثلاث حركات منفصلة.
5. جهة الاستلام تؤكد المستلم أو النقص. التأكيد لا يعيد إضافة الرصيد الذي أضيف بالفعل عند تسجيل التحويل. فرق الكمية يعالج بتصحيح موثق لا بتعديل صامت.
6. تحديث القائمة يحفظ نسختها السابقة. يظهر المتبقي لكل صنف والفروع التي لم ترد وآخر تحديث؛ الإغلاق يمنع طلب كميات جديدة ولا يمحو التاريخ.

## الحسابات والصلاحيات

اسم حساب «الدعم» لا يمنحه صلاحية مدير. تمنح له صلاحيات نشر ومتابعة وتجهيز مستقلة، ويظل تحريك المخزون بندًا منفصلًا. لا توجد حاليًا هذه البنود الجديدة في البرنامج. لا يسجل التحويل الداخلي كمنصرف مستشفى إضافي؛ نقص المرسل يساوي زيادة المستلم.

## شرط التشغيل

توزيع الطلب على أجهزة الصيدليات فعلًا يحتاج قاعدة مركزية مشتركة معتمدة. النسخ المحمولة المنفصلة لا تتراسل وحدها عبر كابل الشبكة. بدون خادم معتمد، العرض على حسابات قاعدة محلية واحدة ليس تعميمًا على أجهزة المستشفى.

الرأي: مفيدة لتقليل الاتصالات وزيادة التتبع، لكن تضاف بعد تثبيت الحسابات والاستيراد والصلاحيات والتشغيل المركزي، ولا تعرض كميزة جاهزة قبل اختبار مدير ودعم ومخزن وفرعين.
